# AP1 Exam Blueprint

Purpose: Define how AP1 topics are usually evaluated and how students should prepare.

---

## Question Format Categories

AP1 questions usually use these formats:

- Definition.
- Comparison.
- Scenario.
- Problem solving.
- Interpretation.
- Calculation.
- Diagram analysis.
- Vocabulary.
- Decision making.

Not every topic uses every format.

---

## Hardware

### Typical Formats

- Definition: CPU, RAM, SSD, HDD.
- Comparison: SSD vs HDD, RAM vs storage.
- Scenario: slow PC, insufficient storage, performance bottleneck.
- Decision making: choose suitable upgrade.
- Vocabulary: Arbeitsspeicher, Massenspeicher, Prozessor.

### How IHK Evaluates

The IHK checks whether students know the role of components and can connect symptoms to causes.

### Common Confusions

- RAM vs SSD.
- CPU cores vs clock speed.
- Storage capacity vs speed.
- GPU vs CPU.

### How To Prepare

- Learn each component's role.
- Practice performance scenarios.
- Compare components in tables.

---

## Operating Systems

### Typical Formats

- Definition: Betriebssystem, Kernel, Prozess.
- Scenario: permissions, file access, boot problems.
- Comparison: process vs thread, user vs group.
- Problem solving: application not starting, access denied.

### How IHK Evaluates

The IHK checks whether students understand how software uses hardware and how OS manages resources.

### Common Confusions

- Program vs process.
- Process vs thread.
- User vs permission.
- File system vs folder.

### How To Prepare

- Explain OS tasks.
- Practice user and permission scenarios.
- Draw process/resource relationships.

---

## Networks

### Typical Formats

- Definition: LAN, WAN, WLAN, DNS, DHCP.
- Comparison: switch vs router, TCP vs UDP.
- Scenario: client has no network, website unreachable.
- Problem solving: IP, DNS, DHCP, firewall.
- Vocabulary: IP-Adresse, Gateway, Port, Protokoll.

### How IHK Evaluates

The IHK checks whether students can identify which network component or service is responsible in a situation.

### Common Confusions

- DNS vs DHCP.
- Switch vs router.
- IP address vs MAC address.
- TCP vs UDP.
- Port vs protocol.

### How To Prepare

- Learn function of each network service.
- Practice troubleshooting chains.
- Use diagrams.

---

## OSI Model

### Typical Formats

- Diagram analysis.
- Layer assignment.
- Device/protocol matching.
- Troubleshooting by layer.

### How IHK Evaluates

The IHK checks whether students can use layers as a thinking model.

### Common Confusions

- Layer 2 switch vs Layer 3 router.
- TCP/UDP at Layer 4.
- HTTP/DNS at Layer 7.
- Physical cable problems vs IP problems.

### How To Prepare

- Memorize layers with meaning.
- Assign examples to each layer.
- Practice troubleshooting from Layer 1 upward.

---

## Security

### Typical Formats

- Definition: confidentiality, integrity, availability.
- Comparison: authentication vs authorization.
- Scenario: phishing, weak passwords, data loss.
- Decision making: choose security measure.
- AP1 explanation: justify protection.

### How IHK Evaluates

The IHK checks whether students understand risks and suitable measures.

### Common Confusions

- Backup vs RAID.
- Authentication vs authorization.
- Encryption vs hashing.
- Availability vs confidentiality.

### How To Prepare

- Learn protection goals.
- Practice company security scenarios.
- Explain why measures help.

---

## Databases

### Typical Formats

- Definition: table, record, attribute.
- Diagram interpretation.
- Relationship analysis.
- Key identification.
- Normalization basics.

### How IHK Evaluates

The IHK checks whether students understand structured data and relationships.

### Common Confusions

- Primary key vs foreign key.
- Row vs column.
- Table vs database.
- Relationship vs attribute.

### How To Prepare

- Read simple ER-like diagrams.
- Practice identifying keys.
- Explain relationships in words.

---

## SQL

### Typical Formats

- Interpret SELECT statements.
- Write simple SELECT.
- Use WHERE and ORDER BY.
- Understand JOIN basics.
- Identify result tables.

### How IHK Evaluates

The IHK checks whether students can read and reason about simple queries.

### Common Confusions

- WHERE vs JOIN condition.
- SELECT columns vs table source.
- UPDATE without WHERE.
- INNER JOIN result logic.

### How To Prepare

- Practice reading queries line by line.
- Predict result sets.
- Use small tables.

---

## Programming Logic

### Typical Formats

- Pseudocode interpretation.
- Trace variable values.
- Conditions.
- Loops.
- Simple error detection.

### How IHK Evaluates

The IHK checks whether students understand program flow.

### Common Confusions

- Assignment vs comparison.
- Loop condition.
- Index position.
- Function call vs function definition.

### How To Prepare

- Trace code manually.
- Write variable tables.
- Explain each step in simple German.

## UML And Modeling

### Typical Formats

- Diagram interpretation.
- Class diagram analysis.
- Multiplicity.
- Use-case recognition.
- Activity flow.

### How IHK Evaluates

The IHK checks whether students can read models used in software development.

### Common Confusions

- Class vs object.
- Attribute vs method.
- Association vs inheritance.
- Multiplicity meanings.

### How To Prepare

- Learn diagram symbols.
- Practice explaining diagrams in words.
- Connect UML to real software examples.

---

## Professional And Project Topics

### Typical Formats

- Document interpretation.
- Process order.
- Decision justification.
- Basic cost/time reasoning.
- Customer communication.

### How IHK Evaluates

The IHK checks whether students understand IT work in a company context.

### Common Confusions

- Lastenheft vs Pflichtenheft.
- Requirement vs solution.
- Documentation vs implementation.
- Aufwand vs Kosten.

### How To Prepare

- Learn project vocabulary.
- Practice scenario-based justifications.
- Read tasks carefully.
